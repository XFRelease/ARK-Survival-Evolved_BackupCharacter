第一章 · 软件总览

软件总览

「备份角色（BackupCharacter）」是一个方舟生存进化服务端 ArkApi 插件：每当游戏保存玩家数据时，自动把该玩家的官方角色档案整文件复制到独立备份盘，按「日期 / SteamID / 等级」三级分层存放。角色损坏、误删、回档纠纷时，把备份拷回存档目录即可把角色恢复到备份时刻的状态。

💾

存档即备份

游戏每次保存玩家数据（自动存档、玩家退出、SaveWorld）都会自动触发备份，无需任何手动操作。

🗂️

日期 / 玩家 / 等级分层

备份按「根目录\日期\SteamID\等级」三级目录存放，想找某天某级某玩家的档案一目了然。

🧬

原文件整备

直接复制官方 .arkprofile / .profilebak 原文件，角色全部数据（等级、经验、印痕、物品栏、状态点）原样保留。

🎚️

低等级过滤

可配置最低备份等级，新号、低级号不占备份盘空间（预置 5 级起备份）。

🔍

自动定位存档目录

自动解析服务器启动参数里的 AltSaveDirectoryName，多存档目录服务器开箱即用。

🔄

配置热重载

控制台 / RCON 执行 BackupCharacter.Reload，改完配置免重启立即生效。

第二章 · 环境要求

环境要求

项目要求
操作系统Windows（服务端为 Windows 版方舟生存进化服务器）
服务端插件框架ArkApi，最低版本 3.5（依据 Output/PluginInfo.json 的 MinApiVersion 字段）
备份磁盘空间备份目标盘需有可用空间。单个角色档案约几 MB，按「每天每等级一份」累积，建议预留数 GB 并定期清理旧日期目录
第三章 · 部署安装

部署安装

以下为拿到编译好的插件后在服务器上的部署步骤。插件英文名为 BackupCharacter，目录与命令名均由它决定。

  1. 确认服务器已安装 ArkApi

    检查服务器目录 ShooterGame\Binaries\Win64\ArkApi\ 是否存在 → 存在则继续；不存在请先安装 ArkApi（最低 3.5）。

  2. 复制插件文件

    把 PluginInfo.json、config.json、BackupCharacter.dll 复制到 ShooterGame\Binaries\Win64\ArkApi\Plugins\BackupCharacter\ → 目录不存在时先创建（开发工程的 一键安装.bat 会自动完成复制与建目录，并支持部署停用副本 BackupCharacter.dll.arkapi）。

  3. 修改备份根目录（关键）

    打开插件目录下的 config.json，把 Backup.RootDirectory 改为你实际存放备份的盘符路径（如 D:\\ArkBackup）→ 建议指定到非系统盘、且不属于服务器存档目录的位置；配置详解见第四章。

  4. 重启服务器

    启动方舟服务器 → 控制台出现「先锋.备份角色(1.0) 先锋方舟服主群:138535385」横幅日志即表示插件加载成功。

  5. 验证备份生效

    等一名 5 级以上的玩家上线后再下线（或等服务器自动存档）→ 到备份根目录检查是否出现「日期\SteamID\等级」目录和 .arkprofile 文件；测试版插件还会在控制台输出「---->备份成功」等调试日志。

若 config.json 缺失或不是合法 JSON，插件加载时会抛出错误 Can't open config.json，插件将无法启动。部署前务必确认配置文件存在且格式正确。
备份根目录 RootDirectory 缺失或留空时插件不会报错，只是静默跳过备份——部署后请务必完成第 3 步并按第 5 步验证一次。
第四章 · 配置详解

配置文件说明

插件启动时读取服务器目录下的 ArkApi\Plugins\BackupCharacter\config.json。

ShooterGame\Binaries\Win64\ArkApi\Plugins\BackupCharacter\
├── BackupCharacter.dll
├── BackupCharacter.pdb
├── PluginInfo.json
└── config.json   ← 插件配置
JSON 里逗号、引号一个都不能少。建议用带 JSON 校验的编辑器（如 VS Code）修改；改前先备份。文件编码为 UTF-8。修改后可在控制台 / RCON 执行 BackupCharacter.Reload 热重载，无需重启服务器。
第四章 · 配置详解

配置总表

本表列出 config.json 的全部配置键，共两组：Backup 控制备份行为，ConsoleEncoding 控制控制台编码。

配置键所在小节兜底值说明
Backup.RootDirectoryBackup无（缺失或为空则不备份）备份根目录（本插件核心配置），预置 E:\\Backup，必改；详见下方 Backup 小节
Backup.MinLevelBackup0（缺失时不限制）最低备份等级，低于该等级的角色不备份；预置 5；详见下方 Backup 小节
ConsoleEncoding顶层auto（缺失/非法时自动）控制台输出编码：auto 按服务器控制台代码页自动选择，gbk / utf8 强制指定；详见下方配置项详解
第四章 · 配置详解

Backup 备份小节（核心配置）

什么意思：Backup 小节控制备份行为——备份存到哪里、从多少级开始备份。

{
  "Backup": {
    "RootDirectory": "E:\\Backup",
    "MinLevel": 5
  }
}
配置键预置值含义与取值
Backup.RootDirectoryE:\\Backup备份根目录（JSON 里反斜杠要写成 \\）。建议改到空间充裕的非系统盘；目录不存在时插件会自动逐级创建
Backup.MinLevel5最低备份等级（整数）。角色当前总等级低于该值时跳过备份；写 0 表示全部备份。不写这个键则默认 0（不限制）
两个易错点：① JSON 字符串里的 Windows 路径必须双反斜杠（E:\\Backup），写单反斜杠会导致 JSON 解析失败；② MinLevel 必须是数字，写成 "5"（带引号）会在存档时触发插件内部异常（插件会记录日志并跳过本次备份，不影响游戏存档，但备份不会生成）。
改完不用重启：控制台 / RCON 执行 BackupCharacter.Reload 即可热生效。
第四章 · 配置详解

ConsoleEncoding 控制台编码

什么意思：控制插件往服务器控制台输出文字时用的编码。不同版本 ArkApi 的服务器控制台编码不同（3.54 为 GBK/ANSI，3.55 为 UTF-8），编码不匹配时控制台中文会乱码。

兜底值：auto（配置缺失或值非法时都按 auto 处理，非法值会在控制台提示一行黄色警告）

{
  "ConsoleEncoding": "auto"
}

怎么修改：可选值共三个（大小写不限）：

取值效果
auto自动探测：控制台代码页为 936 时转 GBK 输出，否则按 UTF-8 原样输出。3.54 / 3.55 服务器都不用改配置，推荐保持默认
gbk强制输出前转 GBK（写 ansi 也可以）
utf8强制 UTF-8 原样输出（写 utf-8 也可以）
第五章 · 备份机制详解

备份机制详解

什么时候备份：插件挂钩了游戏的玩家数据保存函数，每当游戏保存一名玩家的数据时（服务器周期性自动存档、玩家退出 / 掉线、执行 SaveWorld 等），先让游戏正常写完存档，随后立即对该玩家做一次备份。

备份什么：整文件复制该玩家的两个官方角色档案，不做任何格式转换：

文件内容
{SteamID}.arkprofile官方角色档案，内含等级、经验、印痕、物品栏、状态点等全部角色数据
{SteamID}.profilebak游戏自动维护的档案备份文件，与主档案一并复制

存到哪里：按「根目录 \ 日期 \ SteamID \ 等级」三级分层：

E:\Backup\                          ← RootDirectory 配置的根目录
└── 2026-09-10\                 ← 备份发生日期（每天一个目录）
    └── 76561198xxxxxxxx\       ← 玩家 SteamID（每个玩家一个目录）
        └── 105\                ← 备份时的角色总等级（每级一个目录）
            ├── 76561198xxxxxxxx.arkprofile
            └── 76561198xxxxxxxx.profilebak

备份频率（去重规则）：目标等级目录里 .arkprofile 已存在时本次直接跳过——即每个玩家每天每个等级只保留第一份备份。角色当天升级后会自动在新等级目录再存一份，相当于每个等级都留档。想让同一天重复备份，删掉对应等级目录里的文件即可，下次存档会重新生成。

从哪里复制：插件自动定位服务器存档目录——解析 ShooterGame\Saved\Config\WindowsServer\RunServer.cmd 里的 AltSaveDirectoryName= 参数（多存档目录服务器自动适配）；启动参数里没有该项时按官方默认目录 SavedArks 处理。

备份在游戏存档线程内同步完成，单个档案仅几 MB，对存档耗时影响可忽略；备份流程出现的任何异常（如备份盘掉线）都只记录日志跳过，不会影响游戏正常存档。
第五章 · 备份机制详解

恢复角色步骤

玩家角色损坏、误删、被回档投诉时，把备份档案拷回存档目录即可恢复到备份时刻的状态。全程约五分钟。

  1. 找到要恢复的备份

    在备份根目录按「日期 \ SteamID \ 等级」找到目标档案——玩家报「昨天 105 级没了」，就找昨天的日期目录下该玩家 SteamID 目录里等级不高于 105 的最新一级（等级目录名就是备份时的角色等级）。

  2. 关闭服务器

    正常关闭方舟服务器，等待进程完全退出。必须在停服状态下操作，运行中覆盖存档会失败或损坏。

  3. 拷回备份文件

    把备份目录里的 {SteamID}.arkprofile 复制到服务器存档目录（如 ShooterGame\Saved\SavedArks\，多存档目录服务器按 RunServer.cmd 的 AltSaveDirectoryName 定位）覆盖同名文件；存档目录里若有同名 {SteamID}.profilebak，建议把备份里的 .profilebak 一并覆盖，保持两个文件一致。

  4. 启动服务器

    启动服务器，该玩家下次进入游戏时角色即恢复为备份时刻的状态（等级、经验、印痕、物品栏等全部还原）。

  5. （可选）留存事故现场

    覆盖前建议先把存档目录里原来的 .arkprofile 改名留存（如加 .损坏 后缀），万一恢复结果不符合预期可以回退排查。

恢复的是备份时刻的角色，不是玩家记忆里「最后一秒」的角色——备份之后到恢复之前的游戏进度会丢失。去重规则决定了当天同等级只有一份，越早发现角色异常、可回溯的时间点越多。

命令在服务器控制台或 RCON 中输入。插件英文名为 BackupCharacter，因此命令前缀固定为 BackupCharacter.。当前版本没有玩家聊天命令。

第六章 · 命令用法详解

BackupCharacter.Reload 命令详解

作用：让插件重新读取 config.json。改完备份根目录、最低等级等配置不想重启服务器时用它，立即生效。

BackupCharacter.Reload
参数必填缺省值说明
无参数——本命令不带任何参数

反馈：成功时提示 Reloaded config；配置文件缺失或 JSON 损坏时提示 Failed to reload config，同时错误详情写入日志。只能在控制台 / RCON 使用，不是游戏内聊天命令。

第七章 · 常见问题

常见问题

备份文件在哪里？
在 config.json 里 Backup.RootDirectory 配置的目录下（预置 E:\Backup），按「日期\SteamID\等级」三级分层存放。
玩家玩了一天，备份目录里却没有他？
先试这个：① 检查该玩家等级是否低于 Backup.MinLevel（预置 5 级，低于不备份）；② 检查 RootDirectory 是否已改成实际路径（缺失或留空会静默跳过备份）；③ 确认玩家当天没有已经生成过同等级备份（当天同等级只留一份）；④ 都不是则在控制台 / RCON 执行 BackupCharacter.Reload 后让玩家再触发一次存档（下线或等自动存档），部署测试版的还能看控制台「---->」开头的调试日志定位原因。
怎么手动触发一次备份？
没有单独的备份命令。让玩家下线再上线、等服务器自动存档，或在控制台执行一次 SaveWorld，都会触发全部在线玩家的数据保存，从而触发备份。
备份会不会占满磁盘？
每个「玩家 × 日期 × 等级」组合约几 MB。建议定期清理备份根目录里的旧日期目录（如只保留近 30 天）；清理不影响插件运行。
我的服务器用了自定义存档目录（AltSaveDirectoryName），能用吗？
能。插件每次备份时自动解析 RunServer.cmd 里的 AltSaveDirectoryName= 定位存档目录；启动参数没有该项时按官方默认 SavedArks 处理。
恢复角色后等级 / 物品和玩家说的对不上？
恢复的是备份时刻的状态，备份之后的进度会丢失；等级目录名就是备份时等级，可换更低等级的备份目录（更早时间点）再试一次。
备份盘掉线 / 写失败会影响游戏吗？
不会。备份流程出现异常只记录日志并跳过，游戏正常存档不受影响；备份盘恢复后下一次存档会自动继续备份。
控制台中文乱码（方块/问号）？
先试这个：保持 ConsoleEncoding 为 auto（插件按服务器控制台代码页自动选择编码）并执行 BackupCharacter.Reload；仍乱码再按 ArkApi 版本显式指定——3.54 服务器设 gbk、3.55 服务器设 utf8。
插件没加载，控制台提示 Can't open config.json？
先试这个：检查 ArkApi\Plugins\BackupCharacter\config.json 是否存在、文件名拼写是否正确；存在则用 JSON 校验工具检查格式（多逗号、缺引号、路径单反斜杠都会导致解析失败）。
改了 config.json 但没生效？
先试这个：在控制台或 RCON 执行 BackupCharacter.Reload 热重载；若提示 Failed to reload config 说明新配置格式有错，按报错修正后重试。仍不生效则重启服务器。
怎么临时停用插件？
把插件目录下的 BackupCharacter.dll 改名为 BackupCharacter.dll.arkapi（ArkApi 不加载该后缀），重启服务器即可停用；改回 .dll 恢复。
