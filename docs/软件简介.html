软件简介

备份角色 角色档案 自动双保险

方舟生存进化服务端插件：游戏每次保存玩家数据时自动整备官方角色档案，按日期 / 玩家 / 等级分层存放，角色损坏回档一键找回。

01 · 软件定位

软件定位

开服的人都遇到过这种深夜：玩家哭着来找「我角色没了 / 掉级了 / 龙和装备全没了」，而你能做的只有让他重新练——服务器的存档只有一份，坏了就是坏了，官方 .arkprofile 档案一旦损坏或被错误进度覆盖，角色就回不来了。

备份角色（BackupCharacter）就是给这道防线补的双保险：它是基于 ArkApi 的 Windows 服务端插件，挂钩游戏自身的玩家数据保存函数，游戏每次保存一名玩家的数据时，自动把该玩家的官方角色档案原文件整备到独立备份盘，按「日期 / SteamID / 等级」三级分层。要恢复时停服把文件拷回去，重启即回到备份时刻——等级、经验、印痕、物品栏原样还原，与游戏版本、模组、第三方工具全兼容。

数据库不需要，纯文件备份方案，无任何外部依赖

03 · 重点功能

自动备份机制 核心

什么功能：插件挂钩 UPrimalPlayerData.SavePlayerData——游戏引擎保存玩家数据的必经之路。每当游戏保存一名玩家（服务器周期性自动存档、玩家退出 / 掉线、执行 SaveWorld），插件先让游戏正常写完存档，随后立即把该玩家的 {SteamID}.arkprofile 与 {SteamID}.profilebak 整文件复制到备份盘。

什么作用：备份点与游戏存档点完全同步——凡是游戏「记得住」的时刻，备份盘上都有一份对应档案。备份在存档线程内同步完成，单档案仅几 MB，对存档耗时的影响可忽略。

给你的好处：没有它，你要么指望玩家自觉截图留证据（没法定损），要么手工定期拷整个存档目录（又大又慢还容易忘）。有了它，每个角色的每次存档都有据可查，玩家纠纷时直接拿备份说话。

03 · 重点功能

按日期 / 玩家 / 等级分层 核心

什么功能：备份按「根目录 \ 日期 \ SteamID \ 等级」三级目录组织，并内置去重——每个玩家每天每个等级只保留一份备份，升级后自动在新等级目录再留一份。

E:\Backup\
└── 2026-09-10\
    └── 76561198xxxxxxxx\
        └── 105\
            ├── 76561198xxxxxxxx.arkprofile
            └── 76561198xxxxxxxx.profilebak

什么作用：「按天」给出回溯时间轴，「按等级」天然标记档案时点——目录名就是备份时的角色等级。玩家说「昨天 105 级没了」，直接进昨天的日期目录找他的 105 级目录，几秒定位。

给你的好处：没有它，备份堆成一锅乱麻，找档案全靠翻文件时间戳，玩家一多就是灾难。有了它，备份盘本身就是一本按「天 × 人 × 级」编好索引的账本；去重规则还保证了备份盘不会被同一天的重复存档撑爆，容量需求清晰可估算。

03 · 重点功能

低等级过滤与自动适配 特色

什么功能：MinLevel 配置最低备份等级（如 5 级），低于门槛的角色不备份；插件每次备份时自动解析服务器 RunServer.cmd 里的 AltSaveDirectoryName 定位存档目录，未配置时按官方默认 SavedArks 处理。

什么作用：新号、试玩号、刷号不占用备份空间，备份盘只存有价值的角色；多存档目录（多地图 / 多实例）服务器不用改任何配置。

给你的好处：没有它，要么全量备份眼睁睁看备份盘被一次性小号填满，要么给每台服务器手写路径。有了它，一个等级门槛管住磁盘增长，存档目录自动识别——装上改一行配置就能用。

03 · 重点功能

恢复简单 + 配置热重载 特色

什么功能：恢复角色就是「停服 → 把备份档案拷回存档目录覆盖 → 开服」三步，全程约五分钟，无需任何工具；备份根目录、最低等级等配置改完，控制台 / RCON 执行 BackupCharacter.Reload 免重启生效。备份流程还有异常隔离：备份盘掉线等故障只记日志跳过，绝不影响游戏正常存档。

什么作用：恢复路径就是最朴素文件操作，不引入任何私有格式，离了插件备份文件照样能用；调配置不停服、备份故障不停服。

给你的好处：没有它，商业恢复方案要装客户端、导出导入、还可能锁死在人家格式里。有了它，备份是纯官方格式文件，任何时候都攥在自己手里——换插件、换服、甚至手工处理都行，不被任何方案绑架。
